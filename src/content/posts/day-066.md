## 오늘 배운 것

- Attention은 디코더가 단어를 만들 때마다 인코더의 모든 h를 다시 보는 방식이고, Self-Attention은 이걸 LSTM 없이 한 문장 안의 단어끼리 직접 연결하는 것임.
- BERT는 Transformer 인코더만 쌓아서 앞뒤 문맥을 동시에 보는 사전학습 모델임.

## 이론 파트

### 1. Attention (Seq2Seq에 얹은 버전)

- 인코더의 단어별 출력(`outputs`)을 버리지 않고 디코더에 넘겨서, 단어를 하나 만들 때마다 입력 전체를 다시 봄
- 계산 순서: ① query(디코더의 현재 h)와 인코더 각 h를 내적 → 점수 ② softmax → 비율(합 1) ③ 비율대로 h를 섞어 context 생성
- 앞의 컨텍스트 벡터는 문장 전체에 하나였고, Attention의 context는 단어를 만들 때마다 새로 계산함
- Dot Product Attention은 학습할 가중치가 0개임

### 2. Attention의 한계

| 한계 | 내용 |
|---|---|
| 순차 계산 | 인코더가 여전히 LSTM이라 한 칸씩 읽어야 해서 병렬 불가 |
| 인코더 내부 소실 | h1 → h2 → h3로 이어지는 구간은 여전히 LSTM이라 기울기 소실이 남음 |
| 앞쪽 문맥만 앎 | 단방향 LSTM의 h3는 뒤 단어를 모름 |
| 계산량·메모리 | 입력 길이 × 출력 길이만큼 비교하고, 모든 h를 끝까지 들고 있어야 함 |
| 단순 유사도 / 해석 | 가중치 없는 내적이고, weights가 높다고 판단 근거라고 단정할 수 없음 |

### 3. Self-Attention ⭐

- 같은 문장 안에서 단어가 모든 단어(자기 포함)를 참고해 자기 벡터를 새로 만듦. 예: `it`이 `animal`을 높게 봐서 `it`의 벡터에 animal의 의미가 섞임
- 오늘 실습한 Attention과 계산은 같고 대상만 다름(디코더→인코더 vs 같은 문장끼리). 단어 벡터에 학습되는 행렬 W_Q, W_K, W_V를 곱해 q, k, v를 만듦
- Q = 내가 찾는 질문, K = 비교되는 이름표, V = 실제로 가져다 쓰는 내용
- `Attention(Q,K,V) = softmax(Q·Kᵀ / √d_k) · V`. √d_k로 나누는 이유는 칸 수가 커지면 내적이 커져서 softmax가 한 단어로 쏠리기 때문임
- 숫자 예 (설명용으로 q=k=v=x, 단어 3개): x1=[1,0], x2=[0,1], x3=[1,1] → x1의 점수 1, 0, 1 → ÷√2 → softmax 0.401, 0.198, 0.401 → 새 x1 = [0.802, 0.599]
- 점수표는 (n × n) 정사각형이고, 모든 단어가 동시에 계산됨

### 4. Multi-Head Attention ⭐

- Attention 한 번은 한 가지 관점만 보므로, W_Q·W_K·W_V가 서로 다른 Attention(head)을 여러 개 동시에 돌려서 결과를 이어 붙임
- 크기 예: d_model 64, head 4개 → head당 16칸 → 이어 붙이면 다시 64칸. head를 늘려도 전체 크기는 늘지 않음 (원 논문은 512칸을 8개 head로 나눠 head당 64칸)
- head마다 맡는 관점은 사람이 정하지 않고 학습 결과로 달라짐

### 5. Transformer가 푼 것 – 병렬 처리와 장기 기억

| | LSTM(+Attention) | Self-Attention |
|---|---|---|
| 단어 읽기 | 앞 칸이 끝나야 다음 칸 (순차) | 행렬곱 한 번에 전 단어 (병렬) |
| 1번째 → 100번째 단어 거리 | 99칸 거침 | 직접 연결 (1번) |
| 기울기 곱해지는 횟수 | 99번 | 1번 |

- 대신 필요한 장치: 순서를 모르므로 Positional Encoding으로 위치 정보를 더하고, 디코더 학습 때는 마스크로 뒤 단어를 가림
- 병렬화는 주로 **학습**에서 이득이고, 생성은 여전히 한 단어씩 만듦
- Transformer 안의 Attention은 3종류: 인코더 Self, 디코더 Self(마스크), 디코더→인코더(오늘 실습한 것)

### 6. BERT ⭐

- Transformer의 **인코더만** 쌓은 모델 → 문장 이해에 강함 (디코더만 쌓은 GPT는 생성에 강함)
- 양방향: [MASK] 앞뒤 문맥을 한꺼번에 봄 (LSTM·GPT는 앞→뒤)
- 같은 단어도 문장에 따라 벡터가 달라짐. Word2Vec은 단어당 벡터 1개
- 사전학습(MLM: 일부를 `[MASK]`로 가리고 맞히기, 라벨 불필요) → 작업별 파인튜닝. 직접 학습 없이 `from_pretrained`로 불러 씀
- 입력 `[CLS] 문장A [SEP] 문장B [SEP]`, `##는`은 앞 토큰에 이어지는 조각(WordPiece)

## 실습 파트

### 실습 1. Seq2Seq + Attention 번역

**흐름** : 인코더가 `outputs, hidden, cell` 반환 → 디코더가 매 시점 Attention으로 context 생성 → LSTM → fc → 학습(500 epoch, teacher forcing 0.5) → 추론하며 weights를 모아 히트맵

```python
class Attention(nn.Module):
    def forward(self, hidden, encoder_outputs):
        query = hidden[-1]                                  # 디코더 마지막 층의 h: (B, H)
        scores = torch.bmm(encoder_outputs,                 # (B,T,H) @ (B,H,1) → (B,T,1)
                           query.unsqueeze(2)).squeeze(2)   # bmm은 3차원끼리만 곱해서 1짜리 축을 붙였다 뗌 → (B,T)
        weights = torch.softmax(scores, dim=1)              # 입력 단어 T개 방향으로 합 1 = "어느 단어를 몇 % 볼지"
        context = torch.bmm(weights.unsqueeze(1),           # (B,1,T) @ (B,T,H) → (B,1,H)
                            encoder_outputs).squeeze(1)     # 비율대로 섞은 요약 (B,H)
        return context, weights
```

```python
def forward(self, x, hidden, cell, encoder_outputs):        # AttentionDecoder의 핵심
    x = self.embedding(x)                                   # (B,) → (B,E)
    context, weights = self.attention(hidden, encoder_outputs)   # 단어를 만들기 "전"의 hidden으로 어디를 볼지 계산
    lstm_input = torch.cat([x, context], dim=1).unsqueeze(1)     # (B,E+H) → (B,1,E+H): 시간 축 1 추가
    output, (hidden, cell) = self.lstm(lstm_input, (hidden, cell))  # 직전 기억에서 이어서 한 칸 진행
    output = output.squeeze(1)                              # (B,H)
    pred = self.fc(torch.cat([output, context], dim=1))     # (B,2H) → (B,한국어 사전 크기)
    return pred, hidden, cell, weights                      # context를 fc 직전에 한 번 더 붙임
```

- embedding 16, hidden 64 → 디코더 LSTM 입력 80(=16+64), fc 입력 128(=64×2). 디코더가 앞 Seq2Seq보다 무거운 건 Attention 자체가 아니라 context를 이어 붙여서임
- 인코더·디코더 hidden 크기가 같아야 하는 이유: 시작 기억으로 넘김, 내적, context 이어 붙이기

**결과 읽기** (`you went to park yesterday` → 너는 어제 공원에 갔다)

- 가장 많이 본 입력 단어: 너는→yesterday 0.999, 어제→yesterday 0.986, 공원에→park 0.993, 갔다→to 0.946
- 테스트 문장 `i went to school yesterday` 히트맵: 학교에→school 0.99, 어제→yesterday 1.00, 갔다→to 0.84 / school 0.16
- 영어는 school → yesterday 순인데 한국어는 어제 → 학교에 순이라, 진한 칸이 영어 뒤쪽에서 앞쪽으로 움직임 = 어순 뒤집기의 흔적
- 첫 단어(너는/나는)가 you·i가 아니라 yesterday에 몰림: 첫 시점의 query가 인코더 마지막 h를 물려받아서 자기와 내적이 커진 것으로 보임(추정). 갔다→to인 것도 went와 to가 항상 붙어 나와서 어느 쪽을 봐도 맞힐 수 있기 때문임
