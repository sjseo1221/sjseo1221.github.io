## 오늘 배운 것

- 이미지 읽기 → 블러 → Canny → Contour → 도형 판별까지 이어지는 전처리 파이프라인을 실습함.
- 같은 처리를 웹캠 프레임마다 반복해서 실시간 도형 검출로 확장함.

## 실습 흐름

1. 실습1 기본: imread, BGR↔RGB 변환, resize, ROI, 선·도형 그리기
2. 실습2 블러: 점 노이즈(Salt & Pepper)를 평균·중앙값·가우시안으로 비교
3. 실습3 Canny: Sobel로 밝기 변화 확인 → 임계값 비교 → 블러 후 Canny
4. 실습4 Contour: findContours → 면적으로 잡음 제거 → approxPolyDP → 도형 판별
5. 웹캠: 4번의 처리를 `while` 루프 안에서 프레임마다 반복

## 핵심 개념

- **블러 선택**: 점처럼 튀는 노이즈는 중앙값이 가장 잘 지움. 평균·가우시안은 점이 얼룩으로 번짐. 커널을 키울수록 노이즈와 경계가 함께 뭉개짐
- **Canny low/high** ⭐: 밝기 변화량이 high보다 크면 확실한 경계, low보다 작으면 버림, 그 사이는 확실한 경계와 이어져 있을 때만 남김
- **approxPolyDP의 epsilon** ⭐: 윤곽선을 단순화할 때 허용하는 오차 거리. 크면 꼭짓점이 줄고, 작으면 원본에 가까워짐. 둘레의 2%로 잡으면 도형 크기에 비례함
- **원 판별** ⭐: 꼭짓점 수만으로 부족해서 원형도(4π × 면적 ÷ 둘레²)를 함께 확인함

## 핵심 코드

```python
# 윤곽선 찾기 → 면적으로 점 잡음 제거
contours, _ = cv2.findContours(edges, cv2.RETR_EXTERNAL, cv2.CHAIN_APPROX_SIMPLE)
# RETR_EXTERNAL: 굵은 선이 만든 이중 테두리 중 바깥쪽만 가져옴
# CHAIN_APPROX_SIMPLE: 직선 구간의 중간점을 생략 (사각형이 16점으로 저장됨)

large_contours = []
for cnt in contours:
    if cv2.contourArea(cnt) >= min_area:   # 200 같은 숫자를 직접 쓰면 min_area를 바꿔도 반영 안 됨
        large_contours.append(cnt)         # 면적(숫자)이 아니라 윤곽선(cnt) 자체를 담아야 함
```

```python
# 도형 판별
approx = cv2.approxPolyDP(cnt, 0.02 * perimeter, True)  # 둘레의 2%: 크기에 비례한 허용 오차
vertices = len(approx)                                  # 단순화 후 꼭짓점 수
circularity = 4 * np.pi * area / (perimeter ** 2)       # 원에 가까울수록 1

if vertices == 3:
    return "Triangle"
elif vertices == 4:
    return "Quadrilateral"
elif vertices >= 8 and circularity >= 0.85:   # 원은 단순화해도 8각형이 되므로 원형도 필요
    return "Circle"
else:
    return "Unknown"
```

```python
# 웹캠: 실습과 같은 처리를 프레임마다 반복 (면적 기준만 1000으로 올림)
gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
blurred = cv2.GaussianBlur(gray, (5, 5), 0)   # blurred는 Canny 입력으로만 쓰임
edges = cv2.Canny(blurred, 80, 160)
# 웹캠은 배경 무늬와 노이즈로 잡윤곽선이 많아서 200 대신 1000 사용
```

## 🐛 에러 로그

- 메시지: `error: (-215:Assertion failed) npoints > 0 in function 'drawContours'`
- 원인: `large_contours.append(area)`로 윤곽선 대신 면적 숫자를 담음. 개수는 3으로 맞게 나와서 눈치채기 어려웠음
- 해결: `large_contours.append(cnt)`로 수정. 노트북은 앞 셀 결과에 이어 쓰므로 고친 뒤 뒤 셀들을 다시 실행해야 함

**컬러 이미지와 회색조가 똑같이 보임**

**Sobel X에서 가로선이 사라지고, 선이 두 줄로 나옴**
- 처음 내 이해: 가로·세로선이 없어지는 게 이상함
- 실제로는: Sobel X는 좌우 밝기 변화만 봐서 세로 경계만 잡힘 (Y는 반대). 선이 두 줄인 이유는 굵은 선의 양쪽 테두리를 각각 잡았기 때문이며, `convertScaleAbs`가 절댓값을 취해서 둘 다 흰색이 됨. Canny는 X, Y 변화량을 합쳐서 경계의 크기와 방향을 구함

**경계 검출은 왜 하는가**
- 처음 내 이해: 경계만 뽑는 이유를 모르겠음
- 실제로는: 색·질감을 버리고 형태만 남기면 정보량이 줄고, 다음 단계(윤곽선, 도형 판별, 차선 인식 등)의 입력이 됨

**왜 회색조로 바꿔서 넣는가**
- 처음 내 이해: 컬러 그대로 넣으면 안 되는지 궁금함
- 실제로는: 경계는 밝기 변화로 정의되는데 컬러는 채널이 3개라 변화량도 3벌이 됨. 임계값 기준이 하나로 정해지고 계산량도 줄어듦. 대신 색만 다르고 밝기가 비슷한 경계는 사라짐

**블러 결과는 어디에 쓰이는가**

- 실제로는: Canny 입력으로 한 번만 쓰이는 중간 재료임. 잡선을 줄이려는 용도이고, 선명한 도형 이미지에서는 효과가 거의 안 보임
