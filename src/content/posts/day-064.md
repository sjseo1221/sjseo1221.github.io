## 11/10 – 세션 정리

### 에이전트 학습: 환경, 미드트레이닝, RL

에이전트는 챗봇처럼 수정된 코드를 텍스트로 답하고 끝나는 게 아니라, 저장소 상태를 관찰하고 행동(파일 수정, 테스트 실행)을 정하고 그 결과를 다시 입력으로 받는 루프로 동작함. 그래서 학습에는 상태→행동→환경 반응→결과의 궤적과, 성공 여부를 자동으로 검증하고 실패하면 되돌릴 수 있는 환경이 필요함. 에이전트가 볼 수 없는 숨겨진 테스트로 통과 여부를 확인해야 점수만 따는 꼼수를 막을 수 있음.

학습 단계는 사전학습 → 미드트레이닝 → SFT → RL 흐름으로 설명됨. 미드트레이닝은 사전학습 후반에 에이전트형 데이터를 섞어 이후 SFT·RL의 진입 장벽을 낮추는 단계이고, 최근 1~2년 트렌드로 소개됨. 데이터는 강한 모델이나 코딩 에이전트를 실제 환경에서 돌려 궤적을 모으고 가공해서 만듦.

### Hugging Face KREW 번역 자동화

Hugging Face 블로그 한국어 번역에서 문서 선정·번역·품질 검사마다 생기던 병목을 줄이려고 사람 개입을 최소화한 워크플로를 만든 사례임.

- 새 글이 올라오면 GitHub Actions로 번역 초안 PR이 자동 생성됨.
- 품질·SEO 평가 후 에이전트가 자동 수정하며 최대 3회 반복하고, 해결이 안 되면 디스코드 알림으로 사람이 검토함.
- 코드·링크처럼 깨지면 안 되는 요소는 마스킹해서 보호함.
- 용어집·과거 PR 같은 컨텍스트는 많이 넣는다고 좋아지지 않아서, 문서에 맞는 가이드만 골라 압축해 넣었더니 토큰은 줄고 평가 점수는 올랐음.
- 남은 과제는 사람 확인이 필요한 부분, 자동 수정 중 새로 생기는 오류, API 비용임. 저렴한 모델로 문서를 쪼개 번역하는 실험은 모델마다 문체가 달라 일관성이 깨져 성능이 좋지 않았음.

### NCA-GENL 연습문제에서 헷갈린 것

| 헷갈린 것 | 정리 |
|---|---|
| BLEU / ROUGE / Perplexity | BLEU는 번역(precision), ROUGE는 요약(recall), Perplexity는 언어 모델 평가이며 낮을수록 좋음 |
| LoRA vs 양자화 | LoRA는 원본 가중치를 동결하고 저랭크 행렬만 학습, 양자화는 정밀도를 낮춰 메모리·지연을 줄임 |
| TensorRT vs Triton vs NIM | TensorRT는 모델 최적화, Triton은 여러 프레임워크를 서빙하는 서버, NIM은 컨테이너로 포장된 추론 서비스 |
| BERT vs GPT | BERT는 인코더(양방향, 이해), GPT는 디코더(왼쪽→오른쪽, 생성) |
| Softmax / Sigmoid / ReLU | Softmax는 다중 클래스 확률(합 1), Sigmoid는 이진 분류, ReLU는 은닉층 |
| Top-k vs Top-p | Top-k는 상위 k개 고정, Top-p는 누적 확률 p까지로 후보 수가 변함 |
| 컨텍스트 윈도우 vs 배치 vs 에폭 | 컨텍스트 윈도우는 한 입력의 최대 토큰 수, 배치는 동시에 넣는 샘플 수, 에폭은 전체 데이터 한 바퀴 |
| Precision vs Recall | Precision은 예측한 것 중 맞은 비율, Recall은 실제 정답 중 찾아낸 비율 |

## Q&A

- 질문: mmtp가 뭐니 (슬라이드 표기는 MMPT)
- 정리: MMPT는 멀티모달 사전학습(MultiModal Pre-Training)이고, MTP는 한 번에 여러 토큰을 예측하는 별개 개념임.

- 질문: VLM, 옴니 모델이 뭐니
- 정리: VLM은 텍스트+이미지(영상)를 입력받아 주로 텍스트를 출력함. 옴니 모델은 오디오까지 입력으로 받고 모델에 따라 음성도 출력함. OmniEvaluator는 모델이 아니라 NAVER의 평가 시스템 이름임.

- 질문: MoE가 뭐니
- 정리: 전문가 여러 개 중 토큰마다 일부만 골라 계산하는 구조임. 550B-A55B는 전체 550B 중 토큰당 활성 파라미터 55B만 쓴다는 뜻임. 대신 어떤 전문가가 뽑힐지 몰라 가중치를 계속 읽어야 해서 디코드 단계에서 메모리 병목이 생김.

- 질문: KV 캐시 레이시오가 뭐니
- 정리: 새 요청의 프롬프트 토큰 중 이미 계산해 둔 KV 캐시를 재사용한 비율임. 높을수록 prefill 연산이 줄어 응답이 빨라짐.

- 질문: PD 분리가 뭐니
- 정리: Prefill은 연산 병목이고 첫 토큰까지의 시간(TTFT)을 정함. Decode는 메모리 병목이고 토큰 간 지연(TPOT)을 정함. 둘을 다른 GPU 그룹에서 처리하면 서로 방해하지 않고 각각 최적화할 수 있고, 대신 KV 캐시를 옮기는 통신이 필요함.

- 질문: RL, RLVR이 뭐니
- 정리: RL은 직접 해보고 보상을 받아 학습하는 방식임. RLVR은 사람이나 다른 AI가 점수를 매기는 대신 프로그램이 정답 여부(테스트 통과 등)를 자동으로 확인해 보상을 줌. 정답을 자동 확인할 수 있는 분야에만 쓸 수 있다는 한계가 있음.

- 질문: SWE-Gym이 뭐니
- 정리: SWE-bench가 시험지라면 SWE-Gym은 같은 형식의 연습 문제집과 실습실임. 실제 GitHub 저장소의 이슈 약 2,400개와 실행 환경, 판정용 테스트로 구성된 검증 가능한 환경의 대표 사례임.

## 내일의 나에게 퀴즈

1. 550B-A55B에서 A55B는 무슨 뜻인가?
2. 디코드 MoE가 연산 병목이 아니라 메모리 병목인 이유는?
3. P/D 분리에서 prefill과 decode는 각각 어떤 병목이고, 어떤 지표를 정하는가?
4. RLVR이 기존 RLHF와 다른 점은?
5. 번역 평가에는 BLEU, 요약 평가에는 무엇을 쓰는가? 그리고 TensorRT와 Triton의 역할 차이는?

## 정답

1. 토큰당 실제로 계산에 쓰이는 활성 파라미터가 55B라는 뜻임. 전체 파라미터는 550B임.
2. 토큰 하나당 읽는 가중치는 크지만(약 85MB) 연산량은 적어서(약 0.3 GFLOP) HBM 대역폭이 성능을 정하기 때문임.
3. Prefill은 연산 병목이고 TTFT를 정함. Decode는 메모리 병목이고 TPOT를 정함.
4. 보상을 사람이나 보상 모델의 판단이 아니라 프로그램이 정답 여부를 자동 확인해서 주므로 점수를 속이기 어렵고 대량으로 돌릴 수 있음.
5. 요약은 ROUGE임. TensorRT는 학습된 모델을 NVIDIA GPU에 맞게 최적화하는 도구이고, Triton은 모델을 서비스로 서빙하는 서버임.
