## 오늘 배운 것

- 포즈 모델의 `keypoints (N, 17, 2)`에서 어깨·손목 y 좌표를 꺼내고, PCK·OKS·mAP로 정확도를 평가함.
- y 비교와 stage 상태 머신으로 "손 올린 순간"만 세는 카운터를 만듦.
- 이미지 좌표는 y가 작을수록 위쪽이고, 연속 프레임의 `True`를 그대로 세면 폭주하므로 상태 머신이 필요함.

## 실습 흐름

1. 모델 불러오기·추론 → `YOLO("yolo11n-pose.pt")`, `predict()`, `plot()`으로 스켈레톤 그리기
2. 출력값 열어보기 → `result.keypoints.xy`가 `(N, 17, 2)` 텐서(사람 × 관절 × x,y) ⭐
3. 평가지표 → PCK(허용 거리 안 비율), OKS(유사도 0~1), `model.val()`의 mAP ⭐
4. 손 들었는지 판단 → `손목 y < 어깨 y - margin`, 두 손은 `or`로 합침
5. stage 상태 머신 → 올리는 순간에만 `count + 1`, 웹캠(.py)으로 확장

### 1) 키포인트 꺼내기

```python
model = YOLO("yolo11n-pose.pt")   # n=nano(가장 가벼움), -pose=키포인트 작업. -pose를 빼면 검출 모델이라 keypoints가 없음
result = model.predict(source=BUS_URL, verbose=False)[0]   # predict는 Results의 '리스트'를 반환 → [0]으로 사진 1장의 결과를 꺼냄
keypoints = result.keypoints.xy[0].cpu().numpy()           # (N,17,2)에서 첫 사람 → (17,2). .xy는 픽셀 좌표, .xyn은 0~1 정규화 값
```

### 2) PCK 거리 계산과 판정

```python
distance = np.linalg.norm(gt[i, :2] - pred[i])   # gt는 (17,3)이라 v열을 빼야([:2]) (2,)끼리 빼짐. 안 빼면 shape 에러
if distance <= bbox_h * ratio:                   # 허용 거리를 사람 키에 비례시킴. ratio가 작을수록 엄격(0.05 < 0.1 < 0.2)
    correct += 1
```

### 3) 손 들기 판단 + 상태 머신

```python
left_up = left_wrist_y < left_shoulder_y - 30    # y는 작을수록 위. -30은 어깨 근처에서 True/False가 깜빡이는 걸 막는 여유값
hand_up = left_up or right_up                    # 둘 중 하나만 들어도 True. and면 두 손을 모두 들어야 함

if hand_up and stage == "down":                  # 내려간 상태에서 올라가는 '순간'에만
    count += 1
    stage = "up"                                 # 센 뒤 up으로 바꿔야 같은 동작을 다시 세지 않음
elif not hand_up:
    stage = "down"                               # 손을 내려야 다음 카운트 준비
```

- `count`, `stage`는 `while` 밖에서 한 번만 만들어야 프레임이 바뀌어도 상태가 이어짐
- 왼손·오른손을 따로 세려면 `left_stage`, `right_stage`처럼 상태 변수를 손마다 따로 둠. 하나를 공유하면 서로 상태를 지워 버림

## Q&A

- 질문: 손목이 어깨보다 10px 위인 경우(`190` vs `200`)가 왜 `False`인가? `margin`을 0으로 바꾸면 어떻게 되는가?
- 실제로는: 기준선이 `200 - 30 = 170`이라 `190 < 170`이 거짓임. `margin=0`이면 기준선이 200이 되어 `190 < 200`이 참이 되고, 채점에서는 기대값과 달라져 X가 됨. 실제 영상에서는 손목이 어깨 근처에서 흔들릴 때 True/False가 왔다 갔다 함

- 질문: 상태 머신 없이 `sum(seq)`로 센 값(7)이 실제 손 든 횟수(3)와 크게 다른 이유는 무엇인가?
- 실제로는: `sum`은 `True`인 프레임 수를 세므로 3프레임 동안 든 손은 3번으로 셈. 상태 머신은 `False → True`로 바뀌는 순간(down → up)만 세서 3이 나옴. 웹캠은 초당 수십 프레임이라 차이가 훨씬 커짐

## 헷갈리기 쉬운 점 정리

- `results`(리스트)와 `result`(`Results` 객체 1개)는 다름. 리스트에 바로 `.keypoints`를 쓰면 `AttributeError`
- `len(results)`는 이미지 수(1), `len(result.keypoints)`는 검출된 사람 수 N
- `orig_shape`는 `(높이 H, 너비 W)` 순서라 `(x, y)`와 반대 ⭐
- PCK는 0~100(%), `model.val()`의 mAP는 0~1
- COCO의 Left는 화면 왼쪽이 아니라 그 사람 자신의 왼쪽. 어깨 5·6, 손목 9·10 ⭐
- 이미지 좌표는 왼쪽 위가 (0, 0)이고 아래로 갈수록 y가 커짐
- `cv2.circle`, `putText`는 이미지를 직접 덮어쓰므로 `.copy()`한 뒤 그림. 색은 BGR 순서
