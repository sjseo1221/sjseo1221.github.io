## 오늘 배운 것

- IoU로 TP/FP를 가르고, Precision·Recall·mAP로 이어지는 평가 흐름을 정리한 뒤 YOLO11n을 Fine-tuning함.
- 직접 만든 가위바위보 데이터(train 240 / val 60)에서 mAP50 0.994, mAP50-95 0.786이 나옴.

## 이론 파트: Detection 평가 흐름

```
Prediction Box → GT와 IoU 계산 → TP/FP/FN → Precision/Recall → AP → mAP
```

### 1. IoU = 겹친 넓이 / 합친 넓이

- 박스 형식은 `[x1, y1, x2, y2]`이고, 이미지 좌표계는 원점이 왼쪽 위, y는 아래로 갈수록 커짐
- 겹친 넓이만 쓰지 않고 Union으로 나누는 이유는 예측 박스를 크게 그려서 점수를 얻는 꼼수를 막기 위함
- GT=[100,100,300,300], Pred=[150,150,320,320]이면 22,500 / 46,400 ≈ **0.485**. 눈으로 보기엔 많이 겹쳐 보여도 0.5에 못 미침
- 박스 3개 비교 (GT는 같음)

| 박스 | IoU | 특징 |
|---|---|---|
| A [110,110,290,290] | 0.810 | GT 안에 완전히 포함됨 (Union = GT 넓이) |
| B [180,180,350,350] | 0.264 | 30px만 더 밀렸는데 0.485에서 0.264로 급락 |
| C [350,80,460,190] | 0.000 | x가 안 겹치면 y가 겹쳐도 0 |

- 크기가 같아도 위치가 어긋나면 IoU가 크게 떨어지고, 작은 박스(0.25)와 GT를 감싸는 큰 박스(0.25)도 둘 다 낮음. 위치와 크기를 동시에 평가하는 지표임

### 2. IoU Threshold로 TP/FP 판정

- `IoU >= threshold`이면 TP, 미만이면 FP
- 같은 Prediction이어도 기준선만 올라가면 TP가 FP로 바뀜. 예) IoU 0.72는 0.5에서 TP, 0.75에서 FP
- 실제 평가는 **클래스 일치 + IoU**를 함께 보고, 같은 GT를 여러 번 검출하면 첫 번째만 TP이고 나머지는 FP임

### 3. TP / FP / FN → Precision / Recall

```
Precision = TP / (TP + FP)   # 내가 찍은 것 중 정답률
Recall    = TP / (TP + FN)   # 실제 있는 것 중 발견률
```

- TP=6, FP=2, FN=4이면 Precision 0.75, Recall 0.6
- TN은 Detection에서 쓰지 않음. 물체가 없는 박스 후보가 무한히 많아서 셀 수 없음

**Q&A**
- 질문: Precision과 Recall은 무엇이 다르고, 어떻게 구분하는가?
- 처음 내 이해: 두 지표가 비슷해 보여서 계속 헷갈림
- 실제로는: 분자는 둘 다 TP로 같고 **분모만 다름**. Precision의 분모는 내가 찍은 박스 수(TP+FP)라서 쓸데없이 많이 찍으면 떨어짐. Recall의 분모는 실제 정답 수(TP+FN)라서 놓치면 떨어짐. 확실한 것 1개만 찍으면 Precision↑ Recall↓, 아무 데나 잔뜩 찍으면 Precision↓ Recall↑로 서로 trade-off 관계임

### 4. AP, mAP50, mAP50-95 ⭐

- confidence 기준을 바꿔 가며 얻은 (Recall, Precision) 점으로 PR Curve를 그리고, 그 면적이 **AP**. 클래스별 AP의 평균이 **mAP**
- **mAP50**: IoU 0.50 기준 하나로 계산. "물체를 찾았는가"에 가까움
- **mAP50-95**: IoU 0.50, 0.55, ..., 0.95(10단계)로 각각 구해 평균. 박스 위치 정확도까지 평가해서 항상 mAP50보다 낮음

### 핵심 코드

```python

# 원본은 두고 data_runtime.yaml로 따로 저장 → 원본 훼손 방지

# 2) Fine-tuning
model = YOLO("yolo11n.pt")              # -cls가 없는 모델이 Detection용. n은 가볍고 빨라서 웹캠에 적합
model.train(
    data=str(runtime_yaml_path),
    epochs=50, imgsz=640, batch=16,     # OOM이 나면 batch를 8로 줄임
    degrees=10.0,                       # 손이 살짝 기울어진 경우 대비 (기본 0에서 변경)

    scale=0.5,                          # 카메라와의 거리 차이 대비
    hsv_v=0.4,                          # 조명 차이 대비
    patience=15,                        # 15 epoch 동안 개선이 없으면 조기 종료
    plots=True,
)

# 3) 검증

print(metrics.box.map50)   # mAP50
print(metrics.box.map)     # 이름은 map이지만 mAP50-95. 헷갈리기 쉬움
```
