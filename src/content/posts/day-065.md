## 오늘 배운 것

- RNN은 기억(h)을 계속 덮어써서 먼 과거를 잃고, LSTM은 기억을 c(장기 저장)와 h(출력)로 나눠 오래 보존함.
- 단어는 번호 → 임베딩 벡터로 바꿔 쓰고, Seq2Seq는 인코더가 요약한 (h, c)를 디코더가 한 단어씩 풀어냄.

## 이론 파트

### 1. RNN – 기억 h를 다음 시점으로 넘김

- `h_t = tanh(W·h_(t-1) + U·x_t)` : U는 현재 입력 x_t에, W는 이전 기억 h_(t-1)에 곱하는 가중치임
- 같은 U, W를 모든 시점에서 공유함. 펼쳐 그린 셀 여러 개는 같은 셀 하나임
- RNN에도 은닉상태 h가 있음. LSTM은 여기에 c를 추가한 구조임

**Q&A**
- 처음 내 이해: W와 U는 둘 다 정답을 향해 곱해지는 가중치인데 뭐가 다른지 모르겠음
- 실제로는: 둘 다 학습되는 가중치이고 곱해지는 대상이 다름. U는 "지금 들어온 입력", W는 "지금까지의 기억"임

### 2. 기울기 소실

- BPTT = 시간축으로 펼쳐서 역전파함. 시점마다 `W × tanh'`가 반복해서 곱해짐
- 1보다 작으면 곱할수록 0에 가까워져(소실) 먼 과거 입력은 학습이 안 됨. 1보다 크면 폭주함
- 대응: 소실은 LSTM/GRU, 역전파 구간을 잘라 쓰는 Truncated BPTT도 있음

### 3. LSTM / GRU ⭐

- `c_t = f_t×c_(t-1) + i_t×g_t` : 덮어쓰기가 아니라 **더하기**라서 기억이 오래 감
- `h_t = o_t×tanh(c_t)` : c에서 꺼낸 출력. 게이트 3개 = forget(지울 것), input(새로 쓸 것), output(꺼낼 것)
- GRU는 게이트 2개(reset, update)이고 셀 상태(c)가 없음
- `output, (hidden, cell) = lstm(x)` → output = **모든 시점**의 h, hidden·cell = **마지막 시점**의 h, c
- 모양: output (배치, 시간, hidden) [batch_first=True], hidden·cell (층, 배치, hidden) → batch_first는 hidden·cell에 적용 안 됨
- `lstm(x, (h, c))`처럼 두 번째 인자를 주면 0이 아니라 그 기억에서 시작함

**Q&A**
- 처음 내 이해: f_t 같은 게이트 값도 가중치의 일종임
- 실제로는: 가중치로 계산해서 나오는 0~1 값임. 가중치는 학습 후 고정되지만 게이트 값은 입력마다 달라짐

### 4. 임베딩 – 번호로 표의 한 행을 읽어옴

- 표의 행 = 단어, 열 = 차원(칸 수). 단어 번호로 한 행을 복사해 와서 그 벡터를 단어의 표현으로 씀
- `nn.Embedding` 출력 모양 = 입력 모양 + 차원. 입력은 정수(int64)여야 함
- 같은 단어가 여러 번 나오면 같은 행을 복사해 읽고, 학습 때 기울기는 그 행에 누적됨
- 차원(칸 수)은 사람이 정하는 하이퍼파라미터임

**Q&A**
- 처음 내 이해: 단어가 12개면 차원도 12이고, 칸마다 성질을 담는 게 차원임
- 실제로는: 단어 수(12)는 표의 **행 수**, 차원은 **열 수**라서 별개의 값임. 칸마다 성질을 담는다는 비유는 맞지만, 어떤 성질을 담을지는 사람이 정하지 않고 학습으로 정해짐 (보충)

### 5. Word2Vec (Skip-gram)

- (가운데 단어, 주변 단어) 쌍을 만들어 가운데 단어로 주변 단어를 맞히게 학습함. 단어 벡터는 그 부산물임
- 단어마다 벡터가 2개 : 입력용(`embedding.weight`), 출력용(`fc.weight`)
- 벡터가 가까움 = 서로 바꿔 써도 되는 단어(유사도). 같이 자주 나오는 관계(apple–eat)는 입력 벡터·출력 벡터의 내적이 담당함

**Q&A**
- 처음 내 이해: 이 학습은 무조건 "다음에 오는 단어"를 맞히는 것임
- 실제로는: window 안의 앞뒤 주변 단어를 맞히는 것이고, 목표는 다음 단어 예측이 아니라 **단어 벡터 만들기**임

### 6. Seq2Seq ⭐

- 인코더가 문장 전체를 읽고 마지막 (hidden, cell)로 요약함 → 이것이 컨텍스트 벡터
- 디코더는 그 요약을 시작 기억으로 받아 `BOS`에서 출발해 한 단어씩 만들고, `EOS`가 나오면 멈춤
- teacher forcing = 학습 중 다음 입력으로 정답(50%) 또는 내 예측(50%)을 섞어 줌. 추론 때는 항상 내 예측
- 인코더·디코더의 hidden 크기는 같아야 함(요약을 그대로 넘기므로). 임베딩 크기는 달라도 됨
- 한계: 아무리 긴 문장도 벡터 하나(h, c)에 압축 → 앞부분 정보 손실 → Attention으로 이어짐

**Q&A**
- 처음 내 이해: 인코더가 요약한 "64칸"이 hidden 하나임
- 실제로는: hidden 64 + cell 64, **두 개**를 같이 넘김
- 처음 내 이해: 영어와 한국어는 어순이 다른데 뒤에 올 단어의 확률만 학습해서 어떻게 번역함
- 실제로는: 어순 규칙을 따로 가르치지 않음. 정답(한국어 순서)을 한 단어씩 맞히도록 학습하면서 대응 관계를 암묵적으로 익힘

## 실습 파트

### 실습 1. N턴 전 숫자 맞추기 (RNN → LSTM)

**흐름** : 랜덤 숫자 데이터 `(T=20, B=32, F=1)` → 정답 = x를 K칸 뒤로 민 것 → RNN/LSTM → Linear → MSE(회귀)

```python
x = torch.randint(0, 10, (T, B, 1)).float()   # float: RNN 계산은 실수로 하기 때문 / 숫자 하나 = F=1
y = torch.zeros(T, B, 1)                      # 앞 K개 시점은 "K턴 전"이 없으니 0으로 남김
y[K:] = x[:-K]                                # x에서 마지막 K개를 뺀 것을 K칸 아래로 → y[t] = x[t-K]

self.lstm = nn.LSTM(1, hidden)                # nn.RNN으로만 바꾸면 RNN 버전 (나머지 동일)
self.fc   = nn.Linear(hidden, 1)              # 시점마다 h → 숫자 하나. 회귀라 끝에 활성화 없음
def forward(self, x):
    h, _ = self.lstm(x)                       # h: 모든 시점의 h (T, B, hidden). 마지막 (hidden, cell)은 안 씀
    return self.fc(h)                         # (T, B, 1): 시점마다 "N턴 전 숫자" 예측
```

**Q&A** (32명 학생 카드 게임 비유로 이해)
- 처음 내 이해: 32명이 같은 순서로 카드를 받음
- 실제로는: 칸마다 독립적으로 뽑은 난수라서 순서가 모두 다름. 같은 건 받는 타이밍뿐임. 순서가 달라야 숫자를 외우는 지름길이 막히고 규칙을 배움
- 처음 내 이해: 다음에 오는 숫자에 규칙이 있음
- 실제로는: 다음 카드는 완전 무작위이고, 규칙은 "정답 = K턴 전 카드"임. 예측이 아니라 **기억**을 훈련하는 문제임
- 처음 내 이해: 예측할 때 32명 중 누구인지 알려줘야 함
- 실제로는: 불필요함. 열(줄)마다 hidden이 따로 쌓여서 섞이지 않고, 모델은 값이 아니라 **방법**을 배움
- 참고: K=2면 첫 2개 시점의 정답은 모두 0임 (`y` 앞부분을 0으로 채웠기 때문)

### 실습 2. 영화 리뷰 감성분석 (SentimentLSTM)

**흐름** : 리뷰 → 토큰화 → 단어 사전(PAD=0, UNK=1) → 정수 인코딩 → 패딩(+길이 저장) → DataLoader → Embedding → LSTM → 마지막 진짜 단어의 h → Linear(2) → CrossEntropyLoss

```python
self.embedding = nn.Embedding(vocab_size, 16, padding_idx=vocab["<PAD>"])  # PAD 행은 학습에서 제외됨 (보충)
self.lstm = nn.LSTM(16, 32, batch_first=True)   # batch_first: 입력/output을 (배치, 시간, 특징) 순서로
self.fc   = nn.Linear(32, 2)                    # 긍정/부정 점수 2개 (CrossEntropyLoss용)

def forward(self, x, lengths):
    x = self.embedding(x)                       # (B, T) → (B, T, 16)
    output, (h, c) = self.lstm(x)               # output (B, T, 32)
    batch_index = torch.arange(x.size(0))       # [0, 1, ..., B-1]
    last_output = output[batch_index, lengths - 1]   # (B, 32): PAD가 아니라 "마지막 진짜 단어"의 h
    return self.fc(last_output)                 # (B, 2)
```

- 사전은 **학습 데이터로만** 만듦(데이터 누수 방지). 분할은 stratified, 학습은 Adam lr=0.001, 50 epoch, batch 32
- 실습 1은 회귀(MSE, y는 float), 이번은 분류(CrossEntropy, y는 int64)

**Q&A**
- 처음 내 이해: 길이(lengths)는 모델이 알아서 아는 값임
- 실제로는: PAD를 붙이기 전에 **내가 직접 계산해 저장**한 값임. 코드에서는 `lengths - 1`로 마지막 진짜 단어 위치를 찾는 인덱스로만 쓰임
- 처음 내 이해: 32가 배치인지 hidden인지 헷갈림
- 실제로는: 둘 다 32인 우연임. 배치 32 = 한 번에 처리하는 문장 수, hidden 32 = LSTM 기억 칸 수
- 처음 내 이해: 임베딩 16, hidden 32는 정해진 값임
- 실제로는: 사람이 정하는 하이퍼파라미터이고 실험으로 조정함

- 해결: 해당 글자를 삭제함

### 실습 3. Skip-gram으로 단어 벡터 만들기

**흐름** : 문장 → 단어 사전 → (가운데, 주변) 쌍 만들기(window=2) → X, y (288쌍) → `Embedding(…, 8)` → `Linear(8, vocab)` → 2000 epoch(전체 배치) → 코사인 유사도

| 단어 쌍 | 코사인 유사도 |
|---|---|
| apple – grape | 0.945 |
| apple – banana | 0.852 |
| dog – cat | 0.978 |
| car – bus | 0.962 |
| apple – car | 0.596 |

같은 종류끼리는 높고 다른 종류는 낮게 나옴

**Q&A**
- 처음 내 이해: pairs 출력 `(2, 4)`의 숫자는 문장 속 위치임
- 실제로는: 단어 사전의 **번호**임. 첫 문장에서는 번호와 위치가 우연히 같아서 헷갈렸음

### 실습 4. Seq2Seq 영→한 번역

**흐름** : 영·한 문장 쌍 생성(주어·장소·시간 조합) → 단어 사전(번호 3부터, 크기 +3) → X (44,5), y (44,5)=한국어 4단어+EOS → Encoder/Decoder → 학습(1000 epoch, teacher forcing 0.5) → 추론(최대 6번, EOS에서 멈춤)

```python
hidden, cell = encoder(X)                           # 영어 문장 전체를 읽고 (h, c)로 요약. 에포크당 1번만 실행
decoder_input = torch.full((len(X),), BOS)          # 문장 44개 모두 첫 입력은 BOS
loss = 0
for t in range(y.size(1)):                          # 5번 = 한국어 4단어 + EOS
    pred, hidden, cell = decoder(decoder_input, hidden, cell)   # 한 단어만 만들고 기억(h, c)을 이어받음
    loss += criterion(pred, y[:, t])                # 시점마다 오차를 더함
    if torch.rand(1).item() < teacher_forcing_ratio:
        decoder_input = y[:, t]                     # 50%: 정답을 다음 입력으로
    else:
        decoder_input = pred.argmax(dim=1)          # 50%: 내 예측을 다음 입력으로
# 이 아래에서 loss.backward(), optimizer.step() (인코더+디코더 파라미터를 합쳐서 업데이트)
```

- BOS=1, EOS=2라서 영어 단어 13개 → 사전 크기 16, 한국어 12개 → 15임

**Q&A**
- 처음 내 이해: 디코더가 왜 5번 도는지 모르겠음
- 실제로는: 한국어 4단어 + EOS = 5임. EOS를 맞히는 것까지 학습해야 추론 때 멈출 줄 앎
- 처음 내 이해: 디코더 입력 모양이 인코더와 왜 다른지(시간 축이 1) 모르겠음
- 실제로는: 디코더는 한 번 호출에 **한 단어씩** 처리해서 `(배치, 1, 임베딩)`으로 reshape해 LSTM에 넣음
- 처음 내 이해: 인코더가 hidden을 버리고 있음
- 실제로는: 버린 건 단어별 h 모음인 **output**(`_`)이고, hidden·cell은 디코더로 넘김
- 처음 내 이해: 학습도 추론도 같은 반복임
- 실제로는: 학습은 1000 epoch 동안 가중치를 바꾸고, 추론은 문장당 1번 통과하며 `no_grad`로 가중치를 바꾸지 않음

## 오늘의 연결

RNN은 기억이 약해서 LSTM이 나왔고, 그 LSTM을 인코더·디코더로 쌓은 것이 Seq2Seq임. 컨텍스트 벡터 하나에 문장 전체를 압축하는 한계가 Attention의 출발점임.

## 확인 필요

- "임베딩 번호 대신 표의 행을 쓰는 이유"와 `padding_idx` 동작은 (보충)으로 적은 내용이라 수업 자료와 대조 필요
- 유사도 수치는 노트북을 다시 실행하면 조금 달라질 수 있음
- N턴 전 문제는 코드는 K=3, 설명 예시는 K=2로 섞여 있음
