## 오늘 배운 것

- 사전학습된 ViT에 3-클래스 헤드를 새로 붙이고, 헤드만 학습(백본 고정)과 전체 학습(풀 파인튜닝)을 비교함.
- 같은 출발점에서 풀 파인튜닝이 시간은 약 2.4배(에폭당) 들었지만 검증 정확도는 0.8872 → 0.9850으로 올랐음.

## 이론: 용어 정리

- **사전학습**: 대규모 일반 데이터로 모델을 만드는 단계. 우리는 결과물(체크포인트)을 받아 씀
- **파인튜닝**: 사전학습 모델을 내 데이터에 맞게 추가 학습함. 보통 백본까지 포함한 전체 학습(풀 파인튜닝)을 가리킴
- **백본 고정**: 백본 가중치를 잠그고 헤드만 학습함 (`requires_grad = False`)
- 백본은 특징을 뽑는 몸통(`model.vit`), 헤드는 점수를 내는 마지막 층(`model.classifier`)임

| | 백본 고정 | 풀 파인튜닝 |
|---|---|---|
| 학습되는 부분 | 헤드만 | 백본 + 헤드 |
| 속도·메모리 | 빠르고 가벼움 | 느리고 무거움 |
| 적합한 상황 | 데이터·자원이 적을 때, 빠른 기준선 | 데이터가 충분하고 높은 성능이 필요할 때 |
| 학습률 | 비교적 큼 (1e-3) | 아주 작게 (2e-5) |

### 실습 흐름

1. 데이터 확인: train 1034 / validation 133 / test 128장, 클래스 `angular_leaf_spot`, `bean_rust`, `healthy`
2. 사전학습 ViT(`-in21k`)를 불러오면서 분류 헤드를 3개로 교체
3. 백본 고정 후 헤드만 3에폭 학습
4. 모델을 새로 불러와 백본까지 풀어서 2에폭 학습
5. 두 방식 비교와 오분류 이미지 분석

### 핵심 코드

```python
# 헤드 교체: 체크포인트에는 분류 헤드가 없어서 3개짜리 새 헤드가 만들어짐
model = AutoModelForImageClassification.from_pretrained(
    model_id,
    num_labels=num_labels,            # 헤드 출력 크기 (3). 이게 핵심 인자
    id2label=id2label,                # 번호 → 이름 (결과 해석용, 계산엔 영향 없음)
    label2id=label2id,
    ignore_mismatched_sizes=True      # 크기가 다른 헤드가 있어도 에러 없이 새로 만듦 (안전장치)
)
```

```python
# 백본 고정: 잠긴 가중치는 loss.backward()에서 기울기가 계산되지 않음
for param in model.vit.parameters():
    param.requires_grad = False       # 학습에서 제외

# True인 것(=헤드)만 옵티마이저에 넘김. 잠글 땐 False를 대입, 고를 땐 True 조건으로 읽음
optimizer = torch.optim.AdamW(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=1e-3                           # 새 헤드는 큰 학습률로 빠르게 학습
)
```

```python
# 풀 파인튜닝: 전체를 학습하되 학습률을 작게 해서 사전학습된 특징이 망가지지 않게 함
optimizer = torch.optim.AdamW(model.parameters(), lr=2e-5)
```

### 실습 Q&A

- 질문: 새 분류 헤드를 만들 때 `ignore_mismatched_sizes=True`는 필수인가?
- 처음 내 이해: 파인튜닝을 하려면 필수로 True를 줘야 한다고 생각함
- 실제로는: 체크포인트의 헤드 크기와 요청한 `num_labels`가 다를 때만 필요함. `-in21k` 체크포인트는 분류 헤드가 없어서 로드 리포트에 `classifier.*`가 MISSING(새로 초기화)으로 나왔고 크기 불일치는 없었음. 어떤 체크포인트로 바꿔도 에러 없이 돌게 하는 안전장치에 가까움

- 질문: `filter(lambda p: p.requires_grad, ...)`에서 조건이 왜 `False`가 아니라 `True`인가?
- 처음 내 이해: 백본을 잠갔으니 `False`를 줘야 하는 게 아닌가 헷갈림
- 실제로는: `False`는 백본을 잠글 때 값을 대입하는 것이고, `filter`는 조건이 `True`인 것만 남김. 잠기지 않은 것(헤드)만 옵티마이저에 넘기려고 `True`로 읽는 것임. `False` 조건을 주면 반대로 백본만 남아 헤드가 학습되지 않음

- 질문: 체크포인트는 가장 좋았던 가중치를 뜻하는가?
- 처음 내 이해: 체크포인트는 가장 성능이 좋았던 가중치라고 생각함
- 실제로는: 어느 시점의 가중치를 저장해 둔 파일을 뜻함. 가장 좋은 것은 "best 체크포인트"로 따로 부름. `-in21k` 체크포인트는 Google이 사전학습을 마치고 공개한 가중치이지 이 데이터에 최적인 값이 아님
