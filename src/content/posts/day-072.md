## 오늘 배운 것

- 사전학습 YOLO11n으로 `result.boxes`의 좌표(xyxy/xywh), 클래스(cls), 신뢰도(conf)를 직접 꺼내 읽고, Confidence Threshold를 바꿔 가며 결과를 비교함.
- 모델은 파일 이름(`-seg`, `-pose`, `-cls`, `-obb`)이 작업을 정하고, 로컬 OpenCV 웹캠 코드는 Colab에서 돌아가지 않음.

## 실습 흐름

1. `YOLO("yolo11n.pt")`로 모델 로드 → 2. `model(이미지)[0]`으로 추론 → 3. `result.boxes` / `result.names`에서 좌표·클래스·신뢰도 추출 → 4. `conf=`를 바꿔 임계값 비교 → 5. `cv2.VideoCapture` 루프로 웹캠 실시간 적용

## 핵심 개념 ⭐

| 개념 | 정리 |
|---|---|
| `model(...)` 반환값 | 이미지 1장이어도 **리스트**로 반환됨 → `[0]` 필수 |
| `xyxy` | (x1, y1, x2, y2) 좌상단·우하단. `cv2.rectangle`, 이미지 자르기에 사용 |
| `xywh` | (cx, cy, w, h) 중심점 + 크기. 위치 판단에 편함 |
| `xyxyn`, `xywhn` | 이미지 크기로 나눈 0~1 정규화 값. YOLO 라벨 형식은 `xywhn` |
| `cls` | **float 텐서**라서 `names[...]`에 넣으려면 `int()` 필요 |
| `conf` | 박스별 신뢰도(0~1). 박스마다 독립적으로 계산됨 |
| Confidence Threshold | 낮추면 많이 찾지만 오검출↑, 높이면 확실한 것만 남지만 놓침↑ |

## 핵심 코드

### 1) 박스별로 클래스·신뢰도 꺼내기

```python
for i, box in enumerate(result.boxes):
    cls_id = int(box.cls.item())          # cls는 float 텐서(5.0) → names 딕셔너리 키는 int라서 변환
    class_name = result.names[cls_id]     # 숫자 → 이름('bus'). 모델은 번호만 출력하므로 사전 필요
    conf = float(box.conf.item())         # .item()은 원소 1개짜리 텐서 → 파이썬 숫자 (GPU에서 CPU로 자동 이동)
    print(f"{i+1}. {class_name:10s} confidence={conf:.3f}")
```

- `result.boxes.cls`처럼 원소가 여러 개인 텐서에 `.item()`을 쓰면 오류가 남 → 반복문에서 박스 1개씩 꺼낼 때만 사용

### 2) Threshold 비교

```python
for conf_threshold in [0.10, 0.25, 0.50, 0.80]:
    r = model(image_url, conf=conf_threshold, verbose=False)[0]   # 반복마다 새 결과 r 사용
    print(f"conf={conf_threshold:.2f} -> {len(r.boxes)}개")        # result.boxes로 쓰면 항상 같은 값이 나옴
```

- 기본값은 0.25. 0.8에서는 화면 왼쪽에 잘린 person(conf 0.62)이 먼저 사라짐
- `result`를 쓰면 Step 3 결과를 계속 세기 때문에 모든 값이 똑같이 나오는 것이 흔한 실수

### 3) 웹캠 실시간 루프 (로컬 VSCode용)

```python
cap = cv2.VideoCapture(0)                     # 0번 카메라. 실행 중인 컴퓨터에 카메라가 있어야 함
try:
    while True:
        ret, frame = cap.read()               # ret=성공 여부, frame=BGR numpy 배열
        if not ret: break
        annotated = model(frame, conf=0.5, verbose=False)[0].plot()   # 박스가 그려진 BGR 이미지
        cv2.imshow("YOLO11", annotated)
        if cv2.waitKey(1) & 0xFF == ord("q"): break   # waitKey가 있어야 창이 갱신됨, 1ms 대기
finally:
    cap.release()                             # 오류가 나도 카메라를 반드시 해제
    cv2.destroyAllWindows()
```

## 🐛 에러 로그

- 해결: 로컬 VSCode에서 `.py`로 실행하거나, Colab에서는 브라우저 JavaScript로 프레임을 받는 방식을 사용함

## Q&A

**Q1. YOLO 모델 파일 `yolo11n.pt`, `yolo11n-seg.pt`, `yolo11n-pose.pt`는 각각 무엇이 다른가?**
- 처음 내 이해: 파일 이름 끝의 `-seg`, `-pose`가 무엇을 뜻하는지, 같은 모델인지 다른 모델인지 구분하지 못함
- 실제로는: 같은 YOLO11 구조에 출력을 덧붙인 모델임. 파일 이름이 작업을 결정함
  - Detection: 박스 + 클래스 + 신뢰도 → `result.boxes`
  - Segmentation: 박스 + 픽셀 윤곽 → `result.masks`
  - Pose: 사람 박스 + 관절 17개 → `result.keypoints`
  - (보충) `-cls`는 `result.probs`, `-obb`는 `result.obb`에 결과가 담김
- Seg와 Pose도 `result.boxes`를 갖기 때문에 `xyxy`, `cls`, `conf` 사용법은 동일함

**Q2. Colab에서 `cv2.VideoCapture(0)`이 실패한 이유는 무엇이고, 어떻게 실시간 웹캠을 쓰는가?**
- 처음 내 이해: 코드를 실행하면 내 노트북 웹캠이 열릴 것이라고 생각함
- 실제로는: Colab 코드는 구글 서버에서 실행되므로 `VideoCapture(0)`은 서버의 카메라를 찾음
  - 이후 실습에서는 브라우저(JavaScript)가 프레임을 캡처해 서버로 보내고, 서버는 추론 결과를 **도형 좌표(overlay)**로 돌려줌
  - 영상은 브라우저가 직접 재생하므로 끊기지 않고, 박스만 서버 왕복 시간만큼 늦게 따라옴

## Colab 확장 실습 요약 (7가지 작업)

같은 입력이라도 어떤 질문에 답하도록 학습했는지에 따라 출력이 달라짐. 모든 작업 함수를 "이미지 입력 → overlay 출력"으로 통일해서 `run_webcam({이름: 함수})` 한 줄로 전환함

| 작업 | 모델 | 결과 속성 | 학습 데이터 |
|---|---|---|---|
| 분류 | yolo11n-cls | `probs` | ImageNet 1000 (person 클래스 없음) |
| 탐지 | yolo11n | `boxes` | COCO 80 |
| 추적 | yolo11n + ByteTrack | `boxes.id` | COCO 80 |
| 인스턴스 분할 | yolo11n-seg | `masks.xy` | COCO 80 |
| 의미 분할 | DeepLabV3 | 클래스 지도 | VOC 21 (cup 없음) |
| 키포인트 | yolo11n-pose | `keypoints` | person만 |
| 회전 박스 | yolo11n-obb | `obb` | DOTA 15 (항공 사진 전용) |

- 추적은 새 신경망이 아니라 탐지 결과를 프레임끼리 이어 붙이는 알고리즘임. 탐지가 실패하면 추적도 끊김
- `persist=True`는 이전 프레임의 추적 상태를 이어서 쓰라는 뜻이며, 없으면 ID가 계속 1부터 다시 시작함
- 인스턴스 분할은 사람마다 다른 색, 의미 분할은 모든 사람을 한 덩어리로 칠함
- 모델은 학습한 클래스와 시점에서만 동작함 (학습 데이터가 곧 한계)
- 정확도와 속도는 맞교환 관계임 (n 모델, `IMGSZ` 크기)
